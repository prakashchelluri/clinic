# Cubott OPD: 360° audit, 20 Nov 2026

**Do not commit this file while the GitHub repo is public** (see S-03): it lists open security holes.

Code audited: `redesign/ux-audit` at `51fc2d6`, the same commit that is live on Render (`cubott-clinical-pyx9.onrender.com`).

## 1. Verdict

The product is in good shape for a demo and not ready for a real clinic. Screens load without errors, role gating on the server is consistent, the money ledger is mostly single-sourced, and the basics of web security (headers, HTTPS, signed cookie, parameterised SQL, upload allow-lists, immutable audit log) are done properly.

What stops production is a short list, most of it small to fix:

| # | Blocker | Why |
|---|---|---|
| 1 | Platform admin has a known default password (S-01) | Anyone can list and create clinics |
| 2 | Every restart writes demo medicines and invented stock into every clinic (D-02) | A real clinic's inventory starts false |
| 3 | Invoice numbers break at the 10,000th invoice (D-01) | Check-in stops working for everyone |
| 4 | Admin can give itself every permission (S-02) | Discount, refund and stock approvals mean nothing |
| 5 | Refunds, advance use and "session done" can be applied twice (D-03 to D-06) | Money paid back twice, sessions billed twice |
| 6 | A closed day still accepts pharmacy sales and back-dated expenses (D-07) | End of day figures change after closing |
| 7 | Client address is wrong behind Render's proxy (S-04) | "Clinic internet only" and the login throttle do not work |
| 8 | No consent, privacy notice, retention or erasure path (section 9) | DPDP Act duties for health data |
| 9 | Free hosting: 77 s cold start, US region, no backups known (P-01, P-02) | Unusable at a reception desk |
| 10 | Test suite is red and takes 16 minutes; no CI (Q-01) | Nothing guards the next change |

**Auto-login.** The live bundle contains the five demo emails and `demo1234` (measured in the served JS). That is what `VITE_DEMO_LOGIN=1` is for and is acceptable now. It cannot switch on by accident in a normal build: without the flag the buttons and prefilled password are compiled out (the local build shows none). The real risk is the server side, S-01 and S-05: the accounts exist whether or not the buttons show.

**Found sound:** every one of the 239 routes checks a permission; no password hash in any response; SQL is parameterised; uploads have type and size limits and safe storage keys; the audit log cannot be edited; patient-link tokens are 18 random bytes and show first name only; cookie is httpOnly, signed, SameSite=Lax; error messages hide database detail; live site sends CSP, HSTS, nosniff, frame-deny and redirects HTTP to HTTPS; `/.env`, `/.git/config`, `/server.log` are not served.

## 7. UI, accessibility and mobile (measured)

- **Phone width fails on all 10 pages measured.** At 375 px the page is 34 to 168 px wider than the screen (Patients and Inventory worst). Tables need their own scroll box; the page itself should never scroll sideways.
- **Table rows are mouse-only.** Clickable rows with no keyboard access: Billing 112, Patients 25, Inventory 25, Audit 12, Calls 6. Make the name cell a link or give rows `tabindex` and Enter.
- **Billing renders all 111 invoices at once** (469 buttons, no paging), unlike Patients and Calls which page.
- **Small targets on phone:** 37 on Calendar, 21 on Accounts, 112 on Billing under 24 px.
- **Good:** no unnamed buttons and no unlabelled inputs on any of the 11 pages; the check-in dialog has `role=dialog`, `aria-modal` and moves focus to the search box; the sign-in error is announced; there is a per-page error boundary and clear "no access" and "not found" states.
- Not measured: colour contrast, focus rings, screen-reader reading order, dark mode.

## 10. Time-saving opportunities

Estimates, not measurements; the write flows were not timed this round.

**Quick wins**
- Check in: the booked list is already one tap. Add "last visit type and fee" as the default so a returning patient is two taps.
- One time format everywhere (F-03).
- Reports: show "new" instead of four-digit percentages.
- Calls: phone number as a tap-to-copy chip.

**Medium**
- Medicine search from the server instead of the full list (also fixes D-15).
- Billing: page and search like the other tables.
- Tabs and open drawers in the URL so refresh and Back keep the place.

**Larger**
- Phone layouts for the doctor (queue and pad) and the owner (Clinic, Accounts).
